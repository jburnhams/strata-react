# Changelog

## 2026-11-07

**Infinite lists: `useInfiniteLoad` and `InfiniteList`** (branch `claude/project-thread-530xy4`, PR #19, issue #6). Jonathan raised that cursor-paged data had no path through `Load<T>` and `DataView`, so strata-listory built the status mapping, an IntersectionObserver sentinel, a refill effect and a next-page skeleton by hand. He asked for each issue to be solved in a way that advances the library, so the hook returns a `Load<T[]>` that `DataView` takes unchanged, the list is built on `VirtualList` rather than beside it, and removal is keyed so it pairs with `useUndoable`.

- `src/query/infinite.ts` (**new**): `useInfiniteLoad({ queryKey, queryFn, items, itemKey, hasMore, cursorAfter })` over TanStack's `useInfiniteQuery`. It returns an `InfiniteLoad<T>`: a `Load<T[]>` of the items held, plus `more` (`hasMore`, `loadingMore`, `error`, `loadMore`), `dismiss(key)` and `restore(key)`. The hook works out the cursor itself, as `cursorAfter` (default `itemKey`) of the last item held, so it cannot be an offset; it falls back to the last item seen when every held item is dismissed, or when the last page brought back only items already seen, so paging never stops early or asks for the same page in a loop. Pages are merged by key, so an item that shifts across a page boundary is shown once. Dismissals belong to one query key, so switching a filter starts with none. A failed first page is a `Load` error; a failed later page keeps the items and sets `more.error`, and `loadMore` is its Try again.
- `src/components/infinite-list.tsx` (**new**): `InfiniteList` renders `DataView` for the first page (skeleton and empty required) and `VirtualList` for the rows, with one row after the last item: a sentinel watched with a root margin (default 400px) inside the list's scroll region plus a "Show more" button for keyboard and screen-reader users (its words are a required `moreLabel`); `moreSkeleton` while a page loads, with a polite status; an alert row with Try again when a later page fails, during which the sentinel stops asking so a dead server is not called in a loop; and `end` when there are no more. `keepAtLeast` refills a worked-through queue without scrolling. Show more and Try again move focus to the first new item, since the button pressed is gone.
- `src/components/virtual-list.tsx`: **new** `bounded` (a short list scrolls in the same region, capped at `height`, so crossing `virtualizeFrom` changes nothing on screen) and `footer` (rendered after the last row inside the scroll region, which carries `data-strata-scroll` so an observer can use it as its root). Plain rows now carry `data-index` as virtual ones do, and are built only when the list is not virtual (the first push built every row on each render and threw it away, found in review). Existing VirtualList baselines are unchanged.
- `src/index.ts`, `src/query/index.tsx`: export `InfiniteList`, `InfiniteListProps`, `useInfiniteLoad`, `InfiniteLoad`, `InfiniteLoadOptions`, `More`.
- `stories/fixtures/kiln.ts`: **new** `firings`, a log of 137 firings with ids that sort by time. `stories/mocks/handlers.ts`: **new** cursor API `GET /api/firings?after=&limit=` (`firingPage`) with loading, empty, server-error and later-page-error handlers.
- `stories/infinite-list.stories.tsx` (**new**): every state (more to come, loading, empty, failed, loading more, later page failed, every firing), the same from the API through MSW, and an interactive archive queue using `dismiss`, `useUndoable` and `keepAtLeast` (tagged `no-visual`).
- `tests/unit/infinite.test.tsx` (**new**, 13 tests): skeleton then first page, the observer's root and margin, the cursor after the last item held (also after a dismissal, with the dismissed item never shown twice; when every held item is dismissed; and when a page brings back only dismissed items), dismissals reset by a new query key, loading while the end stays in view up to the end note, focus after Show more, a later-page failure and its Try again, `keepAtLeast` refill, empty, and a failed first page. 88 unit tests in all after merging main. Codex's review of the first push found three of the cases these cover (dismissals leaking across query keys, paging stopping when every held item was dismissed, and the VirtualList render cost); the hook's `nextCursor(lastPage, held)` option was replaced by `hasMore` and `cursorAfter` as part of that fix.
- The tests use `installFakeIntersectionObserver` from `strata-react/testing` (PR #15). A local stand-in of the same shape, `tests/utils/intersection.ts`, was used until PR #15 merged and was removed when this branch merged main.
- `tests/integration/package.test.ts`: checks the two new exports resolve.
- `tests/visual/baselines/`: 24 **new** baselines (12 stories, light and dark); all 118 match.
- `README.md`, `CLAUDE.md`: the new exports in the component table, and the infinite path in the stack table.

Not done: the house rule in ux-research (`taste-skill/references/app-screens.md`) says a full list shows its range ("1-50 of 1,284"); `InfiniteList` does not show a total because cursor APIs often do not send one. A product can put it in `end` or above the list. The list scrolls in its own region; a list that scrolls with the window is not supported.

**Surface errors from `useAsyncAction`** (branch `claude/project-thread-wxau7h`, PR #14, issue #9). Issue #9 asked for the hook to return the error, take `onError`, keep `run` stable, and have `AsyncButton` announce the error. In strata-listory every caller had written its own try/catch, error state and rethrow. Jonathan asked for each issue to be solved in a way that moves the library forward, so the error is described the way `useLoad` already describes load errors, and not passed through as the raw `Error.message`. `fetchJson`'s `HttpError` message ("409 Conflict from /api/bookings") is written for logs, not for the person using the screen.

- `src/components/async-button.tsx`: `useAsyncAction(action, { settleMs, onError, describeError })` now returns `{ phase, run, error }`. It used to return a `[phase, run]` tuple and take `settleMs` as its second argument, so callers must change; the release is a minor bump (0.2.0), and ux-research's `^0.1.3` range does not pick it up until its examples are updated. `run` keeps one identity for the component's life because the action and options are read through a ref, so the latest action always runs. `error` is cleared when `run` starts again. `action` may now resolve to any value, so `fetchJson` can be passed directly. `AsyncButton` takes `error` and announces "<error> Try again" in its live region. **New** exported types `AsyncAction` and `AsyncActionOptions`.
- `onError` runs in an effect after the error render commits, not inside the catch (found in review of PR #14). Inside the catch, the button is still disabled from `pending` and an error message rendered on `error` does not exist yet, so a callback that moves focus found nothing to focus.
- `src/lib/errors.ts` (**new**): `HttpError`, `DescribeError` and `describeHttpError` moved here from `src/query/` (still re-exported there and from the package, so no import changes), plus **new** `describeActionError`. It uses the same status sentences as loads, but leaves out "Nothing was changed.", because a failed action may still have reached the server. It falls back to the Error's message, and otherwise to undefined, which leaves the retry label on its own.
- `src/index.ts`: exports `describeActionError`, `AsyncAction` and `AsyncActionOptions`.
- `stories/mocks/handlers.ts`: **new** `POST /api/bookings` (201) in the default handlers, and `bookingConflict` (409).
- `stories/async-button.stories.tsx`: `Interactive` uses the new return shape. **New** `InteractiveFailure` (`no-visual`) books against `bookingConflict` and shows the hook's `error` next to the button.
- `tests/unit/actions.test.tsx`: eight **new** tests. They cover `onError` moving focus to an error message, the error announcement, the thrown message, `onError`, the error clearing on retry, a value with no message, the stable `run`, the latest action running, an `HttpError` from MSW described in a sentence, and a custom `describeError`. There are 54 unit tests in all.
- `README.md`: the Actions row describes the new return value and the error announcement.

**Build strata-react out from the library template into an opinionated React + Tailwind framework** (branch `claude/project-thread-nwljes`). Jonathan asked for strata-react to become his own component, UX and styles library based on the ux-research findings, used first for the ux-research examples and live demos and then elsewhere, with Storybook and visual regression testing (headless Chromium screenshots compared with pixelmatch in CI). While the work was under way he fixed the stack: Vite and Vitest, Testing Library, MSW instead of module mocks, TanStack Query, Table and Virtual, React Router, and @napi-rs/canvas only for testing canvas drawing; and he asked for all of it to be written into `CLAUDE.md`. The design follows ux-research `ui-library/` (placeholder name Plinth) with one change: Plinth specified a shadcn-style copy-in registry, and Strata is a package, because Jonathan wants one shared framework across his products. The app still owns its theme; the components are the package's.

- `package.json`: renamed from the template's `my-library` to `strata-react`; ESM-only exports for `.`, `./testing` and `./strata.css`; React 19, React Router, TanStack Query and Tailwind v4 as peers; TanStack Table and Virtual, cva, clsx, tailwind-merge, Radix Slot and Lucide as dependencies; Playwright pinned to an exact version so baselines and CI use the same Chromium; `prepare` builds, so the package installs from GitHub.
- `src/` (**new** contents; the template's hello-world removed): eleven components ported from ux-research `ui-library/examples/components/ui/` (Button, IconButton, AsyncButton, Field and controls, Status, Metric, DataView, DataTable, LineChart, PageHeader, UndoBar, Done), plus **new** `AppShell`, `SideNav`, `Breadcrumb` (React Router `NavLink`), `Tabs` (state in a URL search parameter, ARIA tabs keyboard model), `VirtualList` (TanStack Virtual), and `src/query/` (`createQueryClient`, `StrataQueryProvider`, `useLoad`/`toLoad` from a TanStack query to `Load<T>`, `fetchJson`, `HttpError`).
- `src/components/data-table.tsx`: now built on TanStack Table, keeping the example's small column API; virtualises from 100 rows with a sticky header; `sortParam` keeps the sort in the URL. TanStack Table 8.21 is used rather than 9.x (released August 2026), whose API was not reviewed for this pass.

- Fixes from the first review of PR #1 (Codex): `useUndoable` now commits a pending removal when its screen unmounts inside the undo window instead of dropping it; `fetchJson` normalises `Headers` and tuple-array headers before adding `Accept`, so a caller's `Authorization` is kept; `LineChart` gives all-zero data a positive extent instead of NaN coordinates; `Field` takes an `id` and its id always wins over a control's own, so the label never points at nothing.
