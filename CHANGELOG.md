**RouteMap: tiles under the last pixel column (branch `claude/routemap-tile-edge`)**. Jonathan asked for the RouteMap flake to be looked at: `data-routemap--centred-later--dark` failed the visual job on #206's first run and passed on the single re-run. It is not the marker flake fixed earlier; the diff is one pixel column at the map's right edge (x=774 of the shot), where the baseline has the map's background and the failing run has a tile.

- Cause, found by reproducing it (8 `strata-visual` runners at once failed that shot in 10 of 16 runs, 1233 pixels every time): Leaflet 1.9.4 chooses tiles from `floor(centre) ± size / 2` (`GridLayer._getTiledPixelBounds`) but places the map pane at `round(centre - size / 2)`. The centre of a centred follow is a whole pixel plus or minus the float noise of projecting it back from the pane's position, so `floor` lands a pixel low about half the time and the last column has no tile under it, unless a tile from an earlier view survives (`keepBuffer`). So the same view was drawn two ways depending on the path to it, which the centred follow was built to avoid. The committed baseline had recorded the unlucky way (the failing run's image is byte-identical to the new baseline).
- `src/map/route-map.tsx`: `coveringTiles` is a tile layer that asks for one pixel more on every side (it overrides Leaflet's private `_getTiledPixelBounds`); `RouteMap` uses it. Not exported from the package.

**`useUndoable`: flush, failures with Try again, and the hook owns which rows are hidden** (branch `claude/project-thread-0n52d4`, PR #17, issue #8).
