## 2026-11-08

**Selectable image grid, Shift-click ranges and an `initial` selection that follows the rows** (branch `claude/project-thread-hvbukq`, PR #39, issue #32). Issue #32, from the Bright Horizons port, asked for a grid of images to choose from: a labelled checkbox per tile, select all shown, Shift-click ranges, an `initial` selection that follows the rows as the data changes, virtualised from about 100 tiles. Asked to solve it for the library as a whole, the range and select-all logic moved out of `DataTable` into one hook both surfaces use, so `DataTable` gains Shift-click too, and `initial` became a rule of `useSelection` rather than a grid feature. The picture is the caller's (`renderImage`), so `Thumbnail` (issue #33, in a parallel branch) fills a tile without either depending on the other.

- `src/components/selectable-grid.tsx` (**new**): `SelectableGrid<T>` (`label`, `rows`, `rowKey`, `renderImage`, `detail`, `selection`, `aspect`, `tileSize`, `virtualizeFrom`, `maxHeight`). Each tile is one `<label>` holding the picture in a fixed-aspect frame, a box on a chip in its corner named "Select <rowLabel>", and a one-line detail, so a click anywhere on the picture toggles it. A chosen tile takes the sunken fill and a primary border, never a ring. Below 100 tiles it is a `<ul>` laid out by CSS `auto-fill`; from 100 it is a labelled, focusable scroll region that measures its width for the column count and renders only the visible rows of tiles (TanStack Virtual), keeping `aria-setsize`/`aria-posinset`. Rows are keyed by the column count, so a resize measures them again. **New** types `SelectableGridProps`, `TileAspect`, `TileSize`.
- `src/components/selection.tsx`: **new** `useSelectRows` (internal): one row, a Shift range from the last row clicked over the selectable rows between (set to the clicked row's new state, as Gmail and Finder do), and "Select all shown", over the rows in display order. `useSelection`'s `initial` now takes keys or a test on the row (**new** type `InitialSelection<T>`) and applies to each row the first time it appears, not only on mount; rows already seen keep the person's choice, and one that left and came back still returns unchosen. The state is reconciled while rendering, compared by key, so new rows paint chosen at once and `rows={data ?? []}` does not loop. `onChange` now drops keys with no row as it sets them (the old effect that forgot them is gone). Keys given as `initial` are read into a set once per value, so a single-use iterable (a generator, `set.values()`) is not used up by the first row (found by the Codex review of PR #39).
- `src/components/data-table.tsx`: the select-all code moved to `useSelectRows`; row checkboxes call its `toggle`, so Shift-click and Shift+Space choose a run in the sorted order shown.
- `src/components/checkbox.tsx`: `onCheckedChange` gets a second argument, `{ shiftKey }` (**new** type `CheckboxGesture`), noted from the mouse press or key press on the label because a change event carries no modifiers. Existing one-argument handlers are unaffected. **New** internal `useShiftNote`, shared with the grid's tiles.
- `src/index.ts`: exports `SelectableGrid`, `SelectableGridProps`, `TileAspect`, `TileSize`, `InitialSelection`, `CheckboxGesture`.
- `stories/selectable-grid.stories.tsx` (**new**): default (thin-glazed pieces chosen, collected pieces disabled), none chosen, small portrait tiles, 400 tiles virtualised, phone width, and with `useSelection`, `initial` and a `BulkBar`. `stories/fixtures/kiln.ts`: **new** `piecePhotos(count)`, kiln 2's unloaded pieces. `stories/fixtures/piece-photo.tsx` (**new**): `PiecePicture`, an inline SVG stand-in for a photo, so baselines need no image files.
- `tests/unit/selectable-grid.test.tsx` (**new**, 14 tests): tile names and disabled tiles, a click on the picture, Shift-click runs both ways and over disabled tiles, Shift+Space, a plain click after a run, select-all mixed and clear, virtualisation with select-all over unrendered tiles, `initial` applied once data arrives and to a next page without undoing a person's choice, keys as `initial`, a single-use iterable as `initial`, no loop on a fresh array, and a `DataTable` range in sorted order. `tests/unit/selection.test.tsx`: the `Checkbox` call now includes `{ shiftKey: false }`.
- `tests/visual/baselines/`: 12 **new** `data-selectablegrid--*` baselines (6 stories, light and dark). The other 218 shots match unchanged.
- `README.md`: the Selection row names `SelectableGrid`, ranges and `initial`. `CLAUDE.md`: building-an-app rule 5 covers the grid and `initial`, and the shot count is 230 (it said 214, already out of date).

**Visual baselines that match on any machine: no system fonts, a comparison that absorbs anti-aliasing** (branch `claude/project-thread-9pzvnj`, PR #30). Jonathan asked for baselines to match regardless of the machine that runs them: bundle every face with fontsource so a system font is never used, and configure pixelmatch to cope with different anti-aliasing, tuned by experiment. The experiment changed the plan: no pixelmatch threshold or pixel allowance separates another rasteriser's anti-aliasing from a changed letter, so the comparison now blurs both images 3×3 first.

The experiment (`strata-visual`'s capture, the 218 shots, compared with the committed baselines, which CI wrote on ubuntu-latest):
- Same pinned Chromium (153) on this cloud runner, as the headless shell and as full Chromium, with font hinting on, and with LCD text on: all 218 pixel-identical to CI's baselines. The launch flags already pin these.
- Older Chromium (140 from Playwright 1.55, and Playwright 1.59's): 2 to 36 shots differ, at most 20 pixels at threshold 0.1, plus two size changes in the 140 build. The one difference that survives every setting is the textarea resize grip in `form-field--states`, which Chromium redrew: a real browser change, which the runner already flags by version.
- GPU rasterisation (`--enable-gpu-rasterization` on SwiftShader), the largest anti-aliasing change available here: all 218 shots differ; under the old settings (threshold 0.1, 20 pixels) 54 fail, with up to 159 pixels. Raising the threshold to 0.2 brings that to 1 failure but lets more real changes through.
- Real changes, injected by CSS or DOM after render: one letter changed in the first text of each shot (182 shots differ), label weight 500 to 600, a 1px nudge of the first button, `--primary` 10% darker, `--border` 20% towards the ink, `--muted-foreground` moved slightly. Plain pixelmatch caught 145 of 182 letter changes at 0.1/20 (8 of them size changes) and fewer as the threshold rose (119 of the 174 same-size ones at 0.2/20, against 137 at 0.1/20), because a changed letter in small text is only 10 to 50 pixels, less than the GPU noise.
- Variants scored by the noise they leave against what they catch: neighbour-count filters on the diff mask still left 98 to 102 noise pixels; a 3×3 box blur before pixelmatch at 0.1 left at most 1 pixel of GPU noise in any shot while catching 172 of 182 letter changes, every weight, nudge and primary change, and the same 140 of 150 border changes as before (the ten it misses are line charts whose grid a 20% border shift does not visibly move at any setting). Threshold 0.05 after the blur let 251 noise pixels through; 0.15 caught 9 fewer letters. Neither old nor new settings catch the small `--muted-foreground` shift (under the 0.1 colour distance everywhere); a tighter threshold would need its own evidence.
- End to end, with the new runner and `STRATA_VISUAL_CHROMIUM_ARGS` set to the GPU flags: "218 of 218 screenshots match their baselines (0 identical, 218 within tolerance)", the worst 1 pixel.
- GitHub runners, against the baselines CI wrote (the `visual-portability` workflow on PR #30): Ubuntu 22.04 x64, all 218 pixel-identical; Ubuntu 24.04 arm64, 130 identical and 88 differing only below the 0.1 colour threshold (0 pixels with or without the blur), so the old settings passed them too; GPU raster on Ubuntu 24.04, all 218 within tolerance, the worst 1 pixel. The cloud runner Claude works in was pixel-identical as well.

**Infinite lists: `useInfiniteLoad` and `InfiniteList`** (branch `claude/project-thread-530xy4`, PR #19, issue #6). Jonathan raised that cursor-paged data had no path through `Load<T>` and `DataView`, so strata-listory built the status mapping, an IntersectionObserver sentinel, a refill effect and a next-page skeleton by hand. He asked for each issue to be solved in a way that advances the library, so the hook returns a `Load<T[]>` that `DataView` takes unchanged, the list is built on `VirtualList` rather than beside it, and removal is keyed so it pairs with `useUndoable`.

- `src/query/infinite.ts` (**new**): `useInfiniteLoad({ queryKey, queryFn, items, itemKey, hasMore, cursorAfter })` over TanStack's `useInfiniteQuery`. It returns an `InfiniteLoad<T>`: a `Load<T[]>` of the items held, plus `more` (`hasMore`, `loadingMore`, `error`, `loadMore`), `dismiss(key)` and `restore(key)`. The hook works out the cursor itself, as `cursorAfter` (default `itemKey`) of the last item held, so it cannot be an offset; it falls back to the last item seen when every held item is dismissed, or when the last page brought back only items already seen, so paging never stops early or asks for the same page in a loop. Pages are merged by key, so an item that shifts across a page boundary is shown once. Dismissals belong to one query key, so switching a filter starts with none. A failed first page is a `Load` error; a failed later page keeps the items and sets `more.error`, and `loadMore` is its Try again.

**Build strata-react out from the library template into an opinionated React + Tailwind framework** (branch `claude/project-thread-nwljes`). Jonathan asked for strata-react to become his own component, UX and styles library based on the ux-research findings, used first for the ux-research examples and live demos and then elsewhere, with Storybook and visual regression testing (headless Chromium screenshots compared with pixelmatch in CI). While the work was under way he fixed the stack: Vite and Vitest, Testing Library, MSW instead of module mocks, TanStack Query, Table and Virtual, React Router, and @napi-rs/canvas only for testing canvas drawing; and he asked for all of it to be written into `CLAUDE.md`. The design follows ux-research `ui-library/` (placeholder name Plinth) with one change: Plinth specified a shadcn-style copy-in registry, and Strata is a package, because Jonathan wants one shared framework across his products. The app still owns its theme; the components are the package's.
