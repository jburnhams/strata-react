# Changelog

## 2026-11-07

**Keyboard triage: `useHotkeys`, `KeysLegend`, `useActiveItem`, `ActiveList`** (branch `claude/project-thread-9k96br`, PR #18, issue #7). Issue #7 asked for the keyboard flow written by hand in strata-listory (a window `keydown` handler that skips fields and modifiers, a j/k active item with `aria-current`, focus moving on after an answer) to become part of the library, with a legend so the keys can be found. Jonathan asked for issues to be solved so they advance the library rather than the one app, so the pieces share one shortcut list, work with `useUndoable` and `DataView`, and come with a whole screen that composes them.

- `src/components/hotkeys.tsx` (**new**): `useHotkeys` binds a `Shortcut[]` (or a `{ key: run }` record) on the window and ignores keys typed into inputs, textareas, selects and contenteditable (checkboxes, radios and buttons are not typing), chords with Ctrl, Meta or Alt, IME composition, held keys unless the shortcut is `repeat`, and `disabled` shortcuts. `KeysLegend` renders the same list as a `<dl>` of `<kbd>`s, alternatives read as "j or ↓", disabled ones muted, hidden on coarse pointers. `isTypingTarget` is exported for components with their own key handling.
- `src/components/active-list.tsx` (**new**): `useActiveItem(items, getKey, { initial, noun })` tracks the active item by key, moves it (`next`, `prev`, `first`, `last`, `setActive`), makes it a roving tab stop with `aria-current`, and returns j/k `shortcuts` labelled with the noun. When the active item leaves the list the one that took its place becomes active (the one before it at the end) and focus follows if it was in the list; it never takes focus from elsewhere on the page. It remembers the chosen key, so an Undo that restores the item makes it active again. Fixes from the Codex review of PR #18: after an answer and an immediate Undo, focus now returns to the restored item rather than staying on its successor (so the next key acts on the focused row), and answering two items in a row then undoing restores the second as active, not the item before it. `ActiveList` renders the queue with the arrow keys, Home and End, a rule in ink plus a tint on the active row, and a required `empty`.
- `src/index.ts`: exports the above and the `Shortcut` and `ActiveItem` types.
- `stories/keyboard.stories.tsx` (**new**, `Data/ActiveList`): first active, second active, empty, and the legend. `stories/screens/review-bookings.tsx` and `.stories.tsx` (**new**, `Screens/Bookings to check`): the whole pattern on kiln-room bookings, j/k, a to approve, r to return, z to undo, data through `useLoad` and `DataView`, in its ready, third-active, loading, all-checked and server-error states.
- `tests/unit/keyboard.test.tsx` (**new**, 18 tests): the typing, chord, repeat and disabled rules; the legend's terms; moving, the ends, the arrow keys; moving on after an answer by key and by a row's button; the last item; undo; not stealing focus; the empty state; and the whole screen against MSW. 64 unit tests in all.
- `tests/visual/baselines/`: 18 **new** baselines for the two story files; the other 94 are unchanged.
- `.storybook/preview.tsx`, `.storybook/theme.css`, `package.json`: the fixture theme now bundles JetBrains Mono (`@fontsource-variable/jetbrains-mono`, dev only) as `--font-mono`. The first CI run failed the visual suite by about 22 pixels on every story showing a `<kbd>`, because `font-mono` fell back to whatever monospace face the machine had installed. Every other face the stories use was already bundled.
- `README.md`: a Keyboard row in the component table. `CLAUDE.md`: rule 6 under "Building an app on Strata" says queue screens use these pieces and never a hand-written `keydown` listener.

Not done: `DataTable` has no active-row mode yet, so a triage over a table still needs `ActiveList`; a `?` shortcut that opens the legend in a dialog waits for the Dialog component.

**Build strata-react out from the library template into an opinionated React + Tailwind framework** (branch `claude/project-thread-nwljes`). Jonathan asked for strata-react to become his own component, UX and styles library based on the ux-research findings, used first for the ux-research examples and live demos and then elsewhere, with Storybook and visual regression testing (headless Chromium screenshots compared with pixelmatch in CI). While the work was under way he fixed the stack: Vite and Vitest, Testing Library, MSW instead of module mocks, TanStack Query, Table and Virtual, React Router, and @napi-rs/canvas only for testing canvas drawing; and he asked for all of it to be written into `CLAUDE.md`. The design follows ux-research `ui-library/` (placeholder name Plinth) with one change: Plinth specified a shadcn-style copy-in registry, and Strata is a package, because Jonathan wants one shared framework across his products. The app still owns its theme; the components are the package's.

- `package.json`: renamed from the template's `my-library` to `strata-react`; ESM-only exports for `.`, `./testing` and `./strata.css`; React 19, React Router, TanStack Query and Tailwind v4 as peers; TanStack Table and Virtual, cva, clsx, tailwind-merge, Radix Slot and Lucide as dependencies; Playwright pinned to an exact version so baselines and CI use the same Chromium; `prepare` builds, so the package installs from GitHub.
- `src/` (**new** contents; the template's hello-world removed): eleven components ported from ux-research `ui-library/examples/components/ui/` (Button, IconButton, AsyncButton, Field and controls, Status, Metric, DataView, DataTable, LineChart, PageHeader, UndoBar, Done), plus **new** `AppShell`, `SideNav`, `Breadcrumb` (React Router `NavLink`), `Tabs` (state in a URL search parameter, ARIA tabs keyboard model), `VirtualList` (TanStack Virtual), and `src/query/` (`createQueryClient`, `StrataQueryProvider`, `useLoad`/`toLoad` from a TanStack query to `Load<T>`, `fetchJson`, `HttpError`).
- `src/components/data-table.tsx`: now built on TanStack Table, keeping the example's small column API; virtualises from 100 rows with a sticky header; `sortParam` keeps the sort in the URL. TanStack Table 8.21 is used rather than 9.x (released August 2026), whose API was not reviewed for this pass.
- Changes from the ux-research example code: icons are typed as any `IconComponent`, not Lucide's type; `Done` takes its heading id from `useId` instead of a fixed `done-title` (two on a page collided); `useAsyncAction` clears its settle timer on unmount and on a re-run; `format` became `createFormat(locale)` with a `count()` for plural nouns.
- Fixes from the first review of PR #1 (Codex): `useUndoable` now commits a pending removal when its screen unmounts inside the undo window instead of dropping it; `fetchJson` normalises `Headers` and tuple-array headers before adding `Accept`, so a caller's `Authorization` is kept; `LineChart` gives all-zero data a positive extent instead of NaN coordinates; `Field` takes an `id` and its id always wins over a control's own, so the label never points at nothing. Each has a unit test (46 in all).
- Node 26 (the current LTS, "Lithium") is the target, at Jonathan's request: `engines` is `>=26.0.0`, **new** `.nvmrc`, every workflow runs 26.x, `@types/node` 26, and TypeScript targets ES2024. The browser build's target is unchanged (Vite's default, widely available browsers), since Node only runs the tooling. Build, unit, integration and visual suites all pass on Node 26.13.0.
- `src/styles/strata.css` (**new**): the token contract, namespace reset, type steps, motion utilities and base layer from the example's `globals.css`, without the product's values. Status roles are named (`@theme inline`) but valued by the product; faces default to the system stack; the page title's weight, stretch and tracking are variables (`--title-*`) so a display face is a product decision; non-colour defaults sit in `@layer base` so a product's unlayered values win. Adds `type-display` for Persuade pages. `scripts/copy-css.mjs` appends `@source "./*.js"` in `dist/strata.css` so an app's Tailwind picks up the built components' classes.
- `.storybook/` (**new**): Storybook 10 with react-vite, addon-docs, addon-a11y and msw-storybook-addon; a decorator that gives every story a fresh query client and a `MemoryRouter`, and toolbar globals for theme and density; the kiln-room theme copied from ux-research as a labelled fixture; its own `vite.config.ts` so the library build's settings stay out.
- `stories/` (**new**): 49 stories over 14 files, including "From the API" DataView stories and a whole kiln-room screen that fetch through TanStack Query from MSW (`stories/mocks/handlers.ts`, shared with the unit tests), and the kiln-room sample data as fixtures.
- `scripts/visual.mjs`, `scripts/visual-compare.mjs` (**new**): serves the built Storybook, screenshots every story light and dark in headless Chromium (animations frozen, fonts bundled, four pages at once), compares with `tests/visual/baselines/` using pixelmatch (threshold 0.1, anti-aliasing ignored, 20 stray pixels allowed, a size change always fails), and writes actual, expected and diff PNGs for changes. Tags pick the viewport (`visual-wide`, `visual-phone`) or skip (`no-visual`).
- Visual baselines are clipped to the element under test, at Jonathan's request: `scripts/visual.mjs` now crops each screenshot to the union of what the story paints (text, controls, SVGs, and boxes with a background, border or shadow, each cut to its scroll containers, fixed elements included) plus an 8px margin, and extends past the viewport when the component is larger, instead of a full-page shot of the canvas. A row of buttons is now a 775×56 image rather than 1024 wide with empty space. A story's own viewport tag now beats its file's, which fixed the kiln-room phone story rendering at desktop width.
- `tests/visual/baselines/` (**new**): 94 baselines, written in Playwright 1.63's Chromium on Ubuntu 24.04.
- `tests/unit/` (**new**, 39 tests at first): Testing Library by role and name against MSW, including the query → DataView path in its ready, empty and server-error states with a working "Try again", sorting and URL sort, virtualisation, URL tabs and their keyboard model, undo timing, `Done` focus, and the pixelmatch comparison. `tests/utils/setup.ts` gives jsdom a fixed layout box so measured components render.
- `tests/integration/` (**new**, 5 tests, replacing the template's browser-bundle test): every export resolves; React, the router and TanStack stay out of the bundle; `strata-react/strata.css` compiled by Tailwind in a throwaway app generates the components' classes and none of `bg-indigo-500`, `text-sm`, `rounded-xl` or `shadow-lg`.
- `vite.config.ts`, `vitest.config.ts` (**new**), `tsconfig*.json`: library build with `vite-plugin-dts`; Vitest projects `unit` (jsdom) and `integration` (Node); bundler resolution and JSX.
